# Maven 版本规范

## 1. 版本号格式

`<主版本>.<次版本>.<修订号>[-<限定符>]`

示例：`1.4.2`、`2.0.0-SNAPSHOT`、`1.0.0-RC1`

遵循语义化版本（SemVer）：

- **主版本 MAJOR**：不兼容的 API 变更
- **次版本 MINOR**：向下兼容的功能新增
- **修订号 PATCH**：向下兼容的问题修复

## 2. SNAPSHOT 与 RELEASE

- **SNAPSHOT**：开发中的不稳定版本，如 `1.2.0-SNAPSHOT`。可重复覆盖发布到 `maven-snapshots` 仓库，仅用于联调 / 测试。
- **RELEASE**：正式版本，如 `1.2.0`。发布到 `maven-releases` 仓库后**不可变、不可覆盖**。
- ⚠️ **生产环境禁止依赖 SNAPSHOT 版本。**

## 3. 限定符（Qualifier）优先级

由低到高：

`alpha < beta < milestone(m) < rc < release < sp`

示例：`1.0.0-alpha.1` < `1.0.0-beta.1` < `1.0.0-rc.1` < `1.0.0`

## 4. 命名约束

- 全部小写，分隔符使用 `.` 或 `-`
- 预发布标识用 `-`（如 `1.0.0-rc.1`），构建元数据用 `+`（如 `1.0.0+build.20260824`）
- 不使用中文、空格，不以下划线开头，不加 `v` 前缀

## 5. 版本递增规则

| 变更类型 | 递增位 | 示例 |
| --- | --- | --- |
| 修复 bug | PATCH | 1.2.3 → 1.2.4 |
| 新增功能（兼容） | MINOR | 1.2.4 → 1.3.0 |
| 不兼容变更 | MAJOR | 1.3.0 → 2.0.0 |

## 6. 示例

- ✅ 正确：`1.0.0`、`2.3.1-SNAPSHOT`、`2.3.1-RELEASE`、`1.0.0-RC1`
- ❌ 错误：`v1.0`、`1.0.0.final`、`latest`、`1.0-中文`
